# Resident Feedback and the Evidence Bridge

## Purpose

The Civic Flow Chart should not only help a resident navigate a public process. Where appropriate, it should also help the resident's observation of that process reach the organization responsible for operating, administering, reviewing, or making decisions about the relevant part of the system.

This creates an **evidence bridge** between lived experience and institutional learning.

The goal is not to guarantee a particular policy outcome. The goal is to make the path from observation to responsible review visible, traceable, and usable.

## Basic flow

**PEOPLE REPORT → SYSTEM ROUTES → RESPONSIBLE PEOPLE REVIEW → AUTHORIZED ACTOR DECIDES → RECORD/RESPONSE → MAP UPDATES IF NEEDED**

The person receiving a report and the person legally authorized to make a decision may be different. The map should show that distinction.

## What the bridge should provide

A report or complaint should, where appropriate, be able to answer:

1. What happened?
2. Where did it happen in the process?
3. When did it happen?
4. Which office, process, node, or organization is responsible?
5. Was the report received?
6. Where was it routed?
7. What is its current status?
8. Is more information needed?
9. Can the resident correct a routing error?
10. Can the observation contribute to aggregate evidence?
11. What review or decision process, if any, follows?

## Confirmation

Where technically and legally appropriate, confirmation can be provided by email, text, printed receipt, or another accessible method.

A confirmation should identify:

- receipt date/time;
- routing destination;
- reference or tracking information when appropriate;
- status or next review step when available;
- a correction path if the report was misrouted.

Confirmation is not a promise that the report is correct, that the recipient agrees, or that the system will change.

## Why this matters to the Civic Flow model

The existing Civic Flow concepts already identify:

- the next responsible actor;
- clocks and waiting periods;
- friction;
- evidence and source provenance;
- status;
- backtrack and correction;
- the Ledger;
- the Archive; and
- the distinction between authority and explanation.

The feedback bridge connects these pieces.

A resident's report can become an input at a mapped node. The receiving organization can verify it. Repeated observations can become aggregate evidence. An authorized institution can then review or decide whether a process should remain the same or change.

## Individual reports and aggregate evidence

The system should distinguish an individual case from a pattern.

A single report may document an important individual experience. Multiple reports may reveal recurrence, geographic concentration, timing, or another pattern. Neither volume alone nor a single report automatically establishes what policy should be.

The system should preserve provenance so that aggregate information can be understood in context.

Useful distinctions include:

**OBSERVATION → REPORT → ROUTING → VERIFICATION → AGGREGATION → REVIEW/DECISION**

## Feedback is not the same as a survey

A standing feedback channel and a formal survey have different purposes.

A survey can ask a defined population a defined set of questions. A standing feedback path can capture observations when people actually encounter a problem or unusual condition.

Both can be useful forms of evidence. The Civic Flow Chart should not assume either one is sufficient by itself.

## Privacy

Public visibility and privacy must be designed separately.

Possible information classes:

- **Private case record** — information needed to handle an individual matter.
- **Restricted information** — information that should not be publicly exposed.
- **Public aggregate** — appropriately de-identified patterns that can be shared for civic understanding.
- **Public source evidence** — information already legitimately available to the public.

Anonymization alone does not guarantee privacy. A production implementation would require appropriate privacy, security, records-management, retention, and legal review.

## Avoiding a new wall

The feedback system itself must not become another gatekeeper.

A resident should not be required to understand a complicated Civic Flow interface before being able to report a problem. If the system cannot determine the correct destination, it should provide a reasonable fallback route rather than simply rejecting the person.

A report that is routed incorrectly should have a backtrack/correction path.

The system should also guard against becoming a complaint warehouse. Routing, status, verification, disposition, and aggregate use are more useful than simply accumulating messages.

## Institutional learning

The evidence bridge is intended to support a continuing loop:

**USE OF SYSTEM → OBSERVATION → REPORT → RESPONSIBLE REVIEW → DECISION/RESPONSE → RECORD → MAP REVIEW**

This means the public process can generate information about how it actually operates without treating every observation as an automatic instruction to change it.

The same information can serve different roles:

- the resident uses it to seek help or report a problem;
- staff use it to identify recurring friction or failed handoffs;
- authorized decision-makers use verified evidence when considering changes;
- the public may use appropriately aggregated information to understand system performance;
- the archive preserves what was reported and what happened afterward.

## Design principles

1. **Route the report toward the process owner when that can be determined.**
2. **Distinguish the recipient of a report from the person with decision authority.**
3. **Confirm receipt where practical and appropriate.**
4. **Show status without promising an outcome.**
5. **Allow correction of routing errors.**
6. **Preserve provenance and distinguish observation from verified fact.**
7. **Separate individual case records from public aggregate information.**
8. **Do not treat report volume as automatic proof of a policy conclusion.**
9. **Do not require the Civic Flow system itself to become a prerequisite for ordinary civic access.**
10. **Keep the feedback system lightweight enough that maintaining it does not become a new source of friction.**

## Core principle

> **People should be able to reach the people responsible for the system, and the people responsible for the system should be able to see the evidence produced by its use.**

The Civic Flow Chart is the bridge and map. It is not the decision-maker.
